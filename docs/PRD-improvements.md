# PRD — Mr. Weirdo Jobs 改进版（投得出去 · 投得多 · 别老问）

来源：创始人真实使用反馈（2026-06）+ **对真实数据库（810 个岗位）的漏斗分析**。

## 1. 真正的瓶颈（用数据钉死，推翻了"平台"假设）

实测体验差：投不出去、老报"缺信息"、抓 100 个最后只投几个。拉了真实数据后，结论和直觉相反：

| 发现 | 数字 |
|---|---|
| 岗位在**能投的平台**上（GH/Ashby/Lever） | **776 / 810 = 96%** |
| 投不了的平台（Workday/iCIMS/其他） | 34 / 810 = **仅 4%** |
| fit≥5、平台支持、**该投的** | **413 个** |
| 这 413 里：已投 / 跳过 / **从没投过** | 139 / 28 / **246** |
| 抓到但从没打分 | 134 |

**结论：你的"100→几个"既不是平台问题（96% 能投），也主要不是筛选太严（413 个都过了门槛）。真正原因是——投递批次从没把"够格的存量"投完。246 个该投的、躺着没动。** 代码里没有全局投递上限；是历次只跑了局部/演示批次，而 discovery 几周累积了 810 个，存量越积越多。

> 好消息：你需要的不是又贵又难的 Workday，而是"把已经够格的存量真正投完 + 别因缺信息卡住"——便宜得多。

**附带发现（bug）：** Lever 有完整 driver + dispatch 分支，却没被加进 `SUPPORTED_AUTO_PLATFORMS`（`shared/sourcing/apply_url_classification.mjs`），导致 Lever 岗位 `auto_apply_eligible=0`、进不了自动队列。一行修复可解锁。

## 2. 决策（创始人已拍板）

**保留相关性门控**（不投完全不相关的岗——你自己当初的要求），其余一切为放量让路：把够格存量投完、缺信息不中止、降门槛、提吞吐。**保留投递前唯一确认门 + truthfulness。**

## 3. 目标（按真实数据重排）

- **G1 投完够格存量 + 吞吐（最大杠杆）**：一次完整运行应**投完所有 eligible 行**（当前 246 个 fit≥5 在等）、给 134 个未打分的补分；**并行投递**让大队列快速清空；**单行缺信息只跳过该行，绝不halt整批**。并在界面明确提示"你有 N 个已够格、可投"。
- **G2 永不因缺信息中止**：一次性建全档案；表单缺**非必填**字段 → 默认/跳过，不中止该申请；只有真正必填项才停**该行**（不是整批），且这类信息一次性集中问（沿用归纳压缩）。对应消除 `stuck_on_same_missing` / `profile_specific_answer_required` / `essay_pending` 这些 skip。
- **G3 放宽筛选 + 修 Lever**：fit 门槛大幅下调（把 313 个 fit5-6、甚至部分 fit<5 放进来）；只硬挡 `suspicious`/诈骗 + 相关性 `too_distant`；**把 Lever 加进 `SUPPORTED_AUTO_PLATFORMS`**（免费解锁）。
- **G4（独立轨道，非个人瓶颈）Workday 平台覆盖**：仅服务**金融机构/留学机构**那个 2B 场景，不是创始人自用的瓶颈。已有 v0.7 脚手架（`shared/workday/`、`mrweirdo-workday` skill）但**从未实测**，且架构是"人工监督单 URL"，不是可批量 driver。Workday 难点真实：账号注册墙、按租户差异大（作者自测纯启发式 <60% 覆盖）、需逐租户手写 config + 实测。**多周工作量 + 持续维护**。除非接下了金融机构合作，否则**不优先**。

## 4. 非目标

- 无相关性的全网无脑投（反伤回复率 + 账号被标记封禁）。
- 移除 truthfulness / 移除投递前确认门。
- "每天 1000 秒投完"——真实浏览器操作有物理上限；并行能大幅提速，但不是瞬间。

## 5. 优先级

**P1 = G1 投完存量 + 吞吐 + 单行缺信息不halt整批（命门，且便宜）**
→ **P2 = G2 缺信息不中止该行**
→ **P3 = G3 降门槛 + 修 Lever（一行）**
→ **Workday = 独立 2B 轨道，仅在拿下金融机构合作后启动**

## 6. 实施纪律（沿用本项目一贯做法）

- 高风险/对外真实提交的改动，动代码前先出方案过 PM（同 P2-B / D1 / cover letter）。
- 每步单独 commit、本地跑**完整 CI 每一步**（不只 npm test）、PM 独立验证后再 push。
- truthfulness、queue gate 安全机制、相关性门控（仅调阈值不拆）语义不动。
