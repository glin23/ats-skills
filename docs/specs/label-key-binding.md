# 定稿 — 一道表单题是怎么被判「问用户」还是「系统自己填」的

> 只写当前最新结论。来龙去脉见 `docs/active/2026-07-26_label-key-binding_BUG_REPORT.md`。
> 定稿日期：2026-07-26

## 一句话

**存答案的那个键，同时被当成「这条答的是哪道题」的身份证用**——而认身份的办法只是「键里的词连着出现在题面里」。
包含关系是不对称的：**正着漏认（该不问的还在问）、反着多认（不该填的替你填了）。**

## 判定链路（首次画全，此前散在几个文件里没人写过）

一道题从驱动发出到被判定，要过 **五段 21 道规则**。优先级：

```
标记表（驱动发出的 note） > 18 条题面正则 > 词段兜底
```

**⚠️ 已知半成品**：ADR-3 定的「改由驱动发出的信号主导、题面正则退为兜底」，**只落实了静态 note 那一半**。
动态 note（带后缀的那类，占绝大多数）进不了标记表，**题面正则至今仍在领跑**。这一条本身就是待办。

## 现状规模（实测，107 道真实题面，来自历史投递留痕）

| | 数 |
|---|---|
| 存量假阳性（不该替你填却填了） | **0 / 107** |
| 存量假阴性（已答过还在问） | 2 / 10 |

**但这个面会自我增殖**：把系统自己发布的键写回档案、再跑同一批真实题面，**立刻出 2 处真实假阳性**
（`Name` 盖住 `preferred name`；`School` 盖住「实习后能否转全职」）。**用得越多，认错越多。**

## 两个方向的错不对等（这是全部排序判据）

| 判错方向 | 后果 | 性质 |
|---|---|---|
| 判成「问用户」 | 多问一次 | **有边界、能自愈**（实测：按公布的键写回后不再问） |
| 判成「系统自己填」 | 把不相干的档案值填到表上 | **无边界、不自愈，命中「绝不编造个人事实」红线** |

**宁可多问。** 这条不对等性是本页所有取舍的依据。

## 已拍板的处置（lead 裁决，2026-07-26）

**先 B，再 A，两件都做：**

- **B — 匹配收紧成整题面比对**。代价实测：拍板人本人多答 3 次；代跑的新用户零代价。
- **A — 给键加「这条键管哪道题」的元信息**。
  **⚠️ A 不能挂在 `answer_provenance.json` 上——那会废掉 ADR-4**（来源留痕只用于报告与审计，不参与填表判断）。

## 与「人肉门房代跑」的关系：不受影响（实证）

拿别人的简历代跑、**只跑到打分排序为止**时，这一整类误判**不会产生任何后果**：

- 全链条加载 174 个模块，**缺口报告与提问模块 0 次加载**（阳性对照证明记录器有效）
- 无表单写入、清单里分类器关键词 0 命中、学生档案跑前跑后 sha256 逐字节相同
- 机理：这段代码的输入是投递结果文件，**不真投就没有输入**

**🔴 但线必须守在「打分排序结束」**：一旦点开队列关卡，`apply_batch.mjs` 的静态依赖会把整条分类器链拉进来。

## 两条对上游结论的修正（本轮查实）

1. 验收所称「不产生死锁」**在代码层面不成立**：用户出口是空的、驱动读不到该桶，
   **只有模型编一个值才解得开——编造与死锁二选一**。
2. 「代跑射程为零」**只对通用桶成立**：同族的无条件规则（`:308` `previously employed|work environment`）
   在全空档案上照样判「系统填」，真实题面里已命中 1 条。（不影响代跑，理由见上一节。）
