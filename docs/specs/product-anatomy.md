## 🔴 一个会让后面所有判断失效的前提

**你自己跑的那一版，和别人能装到的那一版，不是同一个东西。**
GitHub 上任何人装到的那一版**落后本地 20 次改动**，这一轮的身份问答修复**一条都不在里面**；
而唯一真跑过这个产品的那台电脑，跑的是**还没提交的**代码。

**只要这两个版本还是两个东西，「我们修好了」在外部就永远不成立。**

## 八大块与状态

一句话：**它是一条装在自己电脑上的求职流水线**——简历进去，一批投出去的岗位和一份报告出来。

| 块 | 干什么 | 状态 | 一句话为什么 |
|---|---|---|---|
| 装机开机 | 装上、每次跑前查环境 | 🟢 能用 | 全新环境装过、自检全绿（沿用 2026-07-25 实测） |
| 认识你 | 简历 → 三份档案 + 身份问答 | 🟡 能跑但不能信 | 活是「说明书交代给模型做」不是代码；且正被改到一半 |
| 找岗 | 5 个渠道抓岗位入库 | 🟢 能用 | 950 个岗位真在库里；**但一条测试都没有——没坏是因为它简单，不是因为有人守着** |
| 挑岗 | 打合适度分 | 🟡 能跑但不能信 | 打分全由模型现场做、无代码无版本；库里 260 个分是上一版标准打的，系统自己不认 |
| 出发前的关卡 | 摆清单等用户点头 | 🟡 能跑但不能信 | **点头看到的清单与真跑那份不是同一份**；「还剩多少能投」三处三个数 |
| 真投递 | 开浏览器填表提交截图 | 🟡 **能跑但不能信（最要命）** | 「投出去没有」靠读页面有没有「成功」字样；标着 success 的截图页面写着「我们没能提交」 |
| 交账 | 出报告 | 🟡 能跑但不能信 | 报告本身没问题（出过 100 份），**但每个数字都来自上面那个不可信的判定** |
| 回音 | 记录公司回没回、提醒跟进 | 🔴 压根没跑起来过 | 库里 950 行：已确认 0、结果状态全「待定」、跟进次数全 0 |

**合计：能用 2 / 能跑但不能信 5 / 从没跑起来 1。**

**命根子 4 块**：认识你、挑岗、真投递、回音。

## 为什么老是打地鼠——三处结构性原因

**一、判断「这是什么」靠「字面里有没有这几个字」。至少 5 处互不相干的实现**，
包括三个平台各自几十条规则的链条（**写的先后顺序就是优先级**），也包括「投出去了没有」本身。
加一条新规则只要往列表里插一行，**而插的那行会不会盖住上面某一行，没有任何东西会告诉你**。
> **这不是某个人写错了，这是这个系统默认的思考方式。**

**二、真正做决定的地方是说明书，管着决定的地方是代码。** 读简历与打分都不是代码，
是写在文档里让模型照做；代码只事后查格式。**说明书改了代码不知道，反之亦然。**
现存证据：主流程说明书写「三道题」，同技能参考文件已改成五题，**两份都在原地**。

**三、同一件事实有好几份，谁也不是权威。**
「还剩多少能投」3 个说法；「我投了几家」3 个说法且在同一张表里（158 / 182 / 183）；
「什么算投出去了」2 套规则；「工作授权怎么答」3 份实现。
> **后果最狠的一点：修好一处不等于修好，而且没有任何东西告诉你还剩几处。**
> 同一问题扫三轮查出 3 处 → 11 处 → 18 处，**那不是扫描不认真，是这个结构在发作。**

## 只修一处，修哪一处（已定）

**修第三处，切口选「什么算投出去了」。**

1. **一刀下去三处都见血**——这件事同时踩着三个坑。
2. **它是唯一交付物的地基**——**在报告顶上那个数字变真之前，这个产品说的每一句话都不能当证据用，包括「我们修好了」。**
3. **它是回音那块的前置**——不先定义它，回音做出来也是建在假地基上。
4. **能被证伪、一句话验收**——同一张表三个数字必须相等，每条「已投」必须拿得出对得上的证据。

**显式放弃**：不先修第一处（体量最大，5 处几十条规则，且**改法早已拍板却一直没动**，说明不适合当「只修一处」）；
不先修第二处（把打分搬进代码 = **把最该由模型干的活变蠢**；正确形态是「给模型产出加代码断言」——**而那就是第三处的做法**）。

## 诚实缺口

装机沿用 7-25 实测本轮未重跑；50 张截图只亲眼核 3 张；未真跑投递；**连续第五轮零一手用户访谈**。
