# 第一个真实用户 — 为什么现在没有，以及从哪来

> **本轮唯一目标（拍板人原话）**：「我希望做的这东西最后能有人用，现在我感觉不会有人用。」
> **能力边界（先说，不藏在末尾）**：我这轮工具箱只有**网络搜索 + 读本仓库代码**。
> **没有网页抓取**——所有外部数字来自搜索结果摘要，我一个原始网页都没打开过，一律标 **C 级**。
> **没有命令行**——所有关于本仓库的判断来自读源码，凡是"跑一下才知道"的地方我显式标了"未实跑"。
> **零一手用户访谈**——这是连续第四轮。本文里没有任何一句"用户会觉得…"是从访谈来的；凡是关于真实学生的判断，我全部标成**假设**，并在第 2 节给出验证它的方法。**这个缺口我不用推理填平。**

---

## 1. Executive Summary（一句话结论）

现在不会有人用，**不是因为门槛高，是因为第一分钟里没有一个字是关于他的**——产品在还没证明任何事之前，先向一个陌生学生索要四项依赖、一份简历、和「以你的名义对外投递」这一整个赛道最重的一次信任授权，而把回报推到 20-40 分钟之后。风险前置、价值后置，这条曲线没人会走完。

**如果只能改一件事换「有人用」：把第一次接触从「你去装」改成「你把简历发我，20 分钟后我给你一份带理由的岗位清单」——人肉门房版首跑（concierge run，创始人在自己机器上代跑，只跑到打分排序为止，绝不替对方投递）。今天就能做，零代码改动。**

它同时是第一次真实访谈、第一次外部人检验我们的打分准不准、和第一次有人拿到属于自己的产出。**代价我认账**：它不可规模化、它兑现的是"有人看到价值"而不是"有人自己跑起来"，这两件事我在第 4 节的指标里分成 M0（看见价值）和 M1（自己跑一轮）两级，不混为一谈。

## 2. Problem Statement（问题陈述与三类证据）

### 2.1 第一分钟到底发生了什么（逐秒，全部有出处）

假设一个在美大学生（非计算机专业）收到创始人发来的仓库链接。**注意：他还没有 Claude Code 或 Codex，这两个是付费的开发者命令行工具——这个假设本身就已经把绝大多数目标人群挡在门外了。** 下面按"他已经装好了"这个最有利的前提往下算：

| 时刻 | 他看到什么 | 出处 |
|---|---|---|
| 第 0-15 秒 | 一句还不错的价值主张：「简历进 → 一份诚实打分的岗位清单和起草好的投递材料出」 | `README.md:15` |
| 第 15-25 秒 | **紧接着的下一屏是一条警告**：「⚠️ 这个工具会真的投出去。运行前请先读免责声明。公开内测用户应仔细复核前几次投递，并理解各平台的服务条款风险」 | `README.md:23-25` |
| 第 25-40 秒 | 依赖清单：macOS、Node 24+、Google Chrome、Claude Code 或 Codex。**四项，缺一不可** | `README.md:41` |
| 第 40-60 秒 | 第二个章节叫「Public Alpha Status」，里面让他跑 `npm run release:alpha` 和 `npm run demo:check`——**这两条是给维护者自己用的发版检查，对一个学生没有任何意义**。README 的第二屏是写给作者自己看的 | `README.md:44-66` |
| 想看看长什么样？ | README 底部链接了「Walkthrough」（实操走查）。点进去第 8-10 行写着：**「不要拿这份文件当安装指南」**——它是 5 月 23 日 v0.2 时代的工程调试日志，正文在讲 `react-select v5 的选择器需要 mousedown 事件而不是 click` | `README.md:192`、`examples/walkthrough.md:8-10`、`:44` |
| 第 2 分钟 | 跑起来后，Step 0 预检**会自动弹出一个新的 Chrome 窗口**（带调试端口的专用 Chrome，跟他平时那个不是同一个、没登录、空白） | `scripts/preflight.sh:24-27`、`README.md:162-174` |
| 第 3 分钟 | 产品对他的第一个要求：**「你要做：发我简历 PDF 的绝对路径。」** | `.claude/skills/mrweirdo-onboard/SKILL.md:120` |
| 第 5-20 分钟 | Step 4 找岗 + 打分，说明书自己标的耗时是 **5-15 分钟**，期间他能看到的只有漏斗数字 | `SKILL.md:261`、`:291` |

**这一分钟里，唯一属于他的东西是零。** 他付出的是：读一条风险警告、装四样东西、交出简历、看一个陌生浏览器弹出来。他拿回的是：几行终端日志。

### 2.2 五个产品层面的病因（不是技术缺陷清单）

**病因一：信任曲线是反的。**
这个产品向陌生人索要的授权，是整个赛道里最重的一档——「用你的名字、你的邮箱、你的简历，在你不在场时，对真实雇主做不可撤销的投递」。而它索要这个授权的时刻是**第一分钟，在它证明过任何事情之前**。对照组：Simplify Copilot 装个浏览器扩展，在你已经打开的表单上帮你填，**提交键还是你自己按**（C 级：官方帮助页与多篇评测的搜索摘要，我未打开原页）；Simplify 那个 4.4 万 star 的实习清单仓库，第一秒就给东西、零索取（A 级：仓库自身状态，第一轮已核）。**我们把最贵的一次索取放在了最便宜的一秒。**

**病因二：兑现价值的时间超过了这类工具的耐心阈值。**
从零到看见一份属于自己的岗位清单：装依赖 + 安装 + 起 Chrome + 交简历 + 5-15 分钟找岗打分，乐观也要 20 分钟，不顺就是 40。有一条广泛流传的经验数字说"首次价值兑现（time-to-first-value）超过 30 分钟，流失率是 10 分钟以内的 3 倍"——**C 级，来自一篇 SaaS 博客的搜索摘要，我没打开原页，数字别当真，方向可参考**。
**但这里有个必须诚实的反面证据**：`career-ops`（我们最同构的对手）的装法是 git clone + npm install + playwright 装 chromium + 跑 doctor，门槛跟我们同量级，第三方教程标题直接写「30 分钟从零到第一次投递」，而它的 star 数比我们大两个量级（C 级，三个口径 34k/60.8k/60.9k 我核不实）。**所以"门槛高"不是充分解释。** 门槛高会杀掉一部分人，但真正让我们停在 0 的是下一条。

**病因三：没有任何一档"先看看"。**
主菜单五个选项，第一个「开始找实习」直接进完整流程（`SKILL.md:26-34`），其余四个是进度跟踪/扩充画像/技能提升/起草材料——**全部预设你已经跑过一轮了**。README 里唯一的稳定路径（`README.md:46-52`）是"装 → 跑 → 过队列关卡 → 真投"。
零件其实是有的：`apply_supervisor.mjs --dry-run`（空跑）就在 Step 5 里跑着（`SKILL.md:333`）。**这不是能力缺失，是没把它做成一个用户看得见的入口。** ——跟蓝图第五节那句「不是功能缺失，是接线缺失」是同一种病。

**病因四：第一分钟说不清这东西给谁用。**
README 100% 英文，「Who It Is For」写的是「US college students」（`README.md:86`）；而产品跑起来的界面是中文优先——`[Step 4/7] 找岗 + 打分`、`你要做`、`自动投 / auto`（`SKILL.md:63-79` 明写"CN-leaning bilingual"）。
一个不懂中文的美国本科生按 README 的承诺装进来，第三分钟撞上中文界面；一个中国留学生（更可能是真实早期用户）撞上的是一整篇英文 README。**两个人群里必然有一个在第一分钟被劝退，而我们没有决定过是哪一个。** 这一条不需要访谈就能确定，因为它是内部矛盾，不是用户偏好。

**病因五：他没法向同学解释这是什么。**
这是我要单独提出来的一条，因为它在过去所有轮次里都没出现过：**用自动投递机器人这件事，本身带社交成本。** 一个学生在群里说"我在用一个自动帮我投实习的工具"，最可能的回应是"那不就是海投机器人吗"。我们真正能反驳这句话的四条（不碰 LinkedIn/Indeed、数据不出本机、不投不相关的岗、不编造事实）**全部压在 README 的「Safety Boundaries」小节里当免责声明用**（`README.md:99-116`）。上一轮我提过一次（竞品调研 §反驳 2），至今没动。
**这条的严重性被低估了**：第一个真实用户几乎必然是创始人的熟人，他愿不愿意用，一半取决于他敢不敢说自己在用。

### 2.3 三类证据（按岗位说明书要求，逐类交代来源）

| 类别 | 内容 | 等级 |
|---|---|---|
| **访谈原话** | **没有。零一手访谈，连续第四轮。** 唯一的"用户原话"是创始人本人（P1，n=1）：「我希望做的这东西最后能有人用，现在我感觉不会有人用」（TASK 关卡 1）、「你有没有工作授权，这没人能知道」（TASK 关卡 3）——**这两句都是创始人的，不是外部用户的。** | A 级（但 n=1） |
| **量化数据** | 岗位 950 / 够格未投 292 / 系统标记可投 20 / 历史已投 183 / `confirmed_at` 非空 **0** / 最后一次投递 2026-06-14（**至今 42 天零投递**）/ 非创始人用户数 **0** | A 级（直接查库，来自 `docs/specs/next-priorities.md`） |
| **"工单"计数** | 我们没有工单系统（没有用户，自然没有工单）。可替代的最接近物是取证报告：50 张投递截图里 **6 张文件名写 `ashby_success`、页面写的是「We couldn't submit your application」**，另 3 张 `post_submit` 画面无确认（TASK Round 18） | A 级（bug 逐张打开核过） |

**这张表最该被读出来的一行是最后一格的"0"和"6"**：我们没有用户，所以我们没有任何来自用户的证据；而我们唯一有的那批一手现场物证，证明的是**产品交出去的数字今天是假的**。

## 3. Personas（用户画像）

**P1 — 创始人本人（唯一被验证的，n=1）**
- JTBD（Jobs to be Done，用户要完成的任务）三维：
  - **功能层**：在 2027 暑期实习的窗口开闸前，把有限的时间投到对的岗位上。
  - **社交层**：不在同学面前显得"没在努力找"；同时**不被归类成"用机器人乱投的人"**（这一维是本轮新加的，见 §2.2 病因五）。
  - **情感层**：摆脱"投了一百多家、一条回音记录都没有、不知道是自己的问题还是运气"的无力感。
- 5 Why 追到底：他要的不是"投满 292 条"→ 是"知道这一季有没有在推进"（上一轮结论）→ **再往下一层是"有人看见了我"**。这解释了为什么 `confirmed_at` 全 0 这件事的分量远超一个字段缺失：**回执是这个情感 job 的唯一兑现物**，其余全是代理指标。

**P2 — 非技术背景的美国大学生（目标画像，纯假设，未验证）**
上一轮标过"纯假设"，本轮**仍然是纯假设**，我不给它加任何新的推测。

**P3 — 在美中国留学生（本轮新提出，同样是假设）**
提出理由只有一条**可核实**的：产品界面已经是中文优先（`SKILL.md:63-79`），且引导流程里工作授权那组题的设计依据（关卡 3 拍板「不许问『你有没有工作授权』」）来自一个 F-1 身份的人的自我观察。**换句话说：产品事实上已经在按 P3 造，但从没承认过。** 这个错配值得在第一轮访谈里当场问清楚，见 §4 的 H3。

> **对照 PROJECT_MEMORY 原则第 3 条**（"单用户期的测试必须喂『不像我』的档案"）：这条原则本来是写给测试的，但它对产品同样成立。**第一批访谈对象和第一批 concierge 简历，必须刻意挑"不像创始人"的**——非商科、非国际生、非同一所学校。否则我们会再一次拿 4/5 碰巧一致的默认值当机制保证。

## 4. 战略上下文（目标对齐 / 市场 / Why now）

**目标对齐**：拍板人的目标是"有人用"，不是"投得多"。这跟 `docs/specs/next-priorities.md` 拍板的执行顺序**不冲突但也不重合**——那份优先级服务的是"跑通一轮拿数据"，服务的对象是创始人自己。

**Why now（为什么是现在，而且窗口很短）**：
**2027 暑期实习的投递窗口从 2026 年 8-9 月开闸。** 亚马逊、Databricks 一类历史上 7-8 月就开；微软、苹果 9 月跟上；咨询（Accenture / Deloitte / EY-Parthenon）与四大的相关岗位 8-9 月开；工程与政府类 8 月起陆续开（**C 级：来自 Extern 与 Simplify 博客的搜索结果摘要，我未打开原页；Simplify 是竞品，其博客有自利动机**）。

今天是 2026-07-26。这意味着：
1. **未来 4-8 周是目标人群焦虑度最高、最愿意试新东西的时段**，也是全年唯一一次"痛点正在发生"的访谈窗口。等到 11 月再去问，问到的全是回忆，不是行为。
2. 同时它也是**风险最高的时段**——如果第一个外部用户在开闸期被产品坑一次（投出去一条不实陈述、或者报告把失败标成成功），损失的不是一个用户，是那一季。

**市场位置（沿用上一轮，无新增调研）**：我们在"本地浏览器机器人全自动投递"这一格，同格的闭源那家口碑塌了、开源旗舰归档了；跟我们最同构的 career-ops 在隔壁格（不替你点提交）活得很好。**这一格空着，可能是机会也可能是坟场。**

## 5. Solution（方案、取舍、排序）

### 5.1 主张：人肉门房版首跑（concierge run）

**做法（今天就能做，零代码）**：
1. 创始人约到一个真实学生，先做访谈（§5.4 的 8 个问题），**不提自己的产品**。
2. 访谈结尾说一句：「我在做一个东西，你把简历发我，我今晚跑一下，明天给你一份排好序的岗位清单，附每一条为什么推荐/为什么跳过。**我不会替你投任何东西。**」
3. 用隔离的家目录跑（`MRWEIRDO_HOME=/tmp/concierge-<代号>`），只跑到 Step 4 结束（找岗 → 打分 → 入库），**不跑 Step 5 队列关卡，不跑任何 `--real`**。
4. 把清单发回去，然后问三个问题：「这里面哪几条你**本来就打算投**？哪几条**明显不对**？如果这份清单每周一早上自动出现在你手机上，你会看吗？」

**为什么是它（这条方案怎么倒回 JTBD 的）**：
- 它兑现**功能层 job 的前半段**（把时间投到对的岗位上），而这恰好是我们**唯一已经跑通、且有 950 行真实数据背书**的能力。
- 它兑现**情感层 job 的一小块**（有人替我看过一遍了）。
- 它**不兑现社交层 job**——他还不能拿它去跟同学说什么。我认这个缺口，不装。
- 它**绕开了三道我们今天过不去的门**：安装门槛（他什么都不用装）、信任门槛（我们不碰他的提交键）、以及产品今天最脏的那部分（真投链路上的三处不实陈述与假成功截图，见 §7）。

**它同时是四件事的载体**：第一次真实访谈 / 第一次外部人检验打分准不准 / 第一次有人拿到属于自己的产出 / 第一次知道 README 首屏该写什么（用他们的原话写，而不是创始人脑补）。

### 5.2 取舍面（显式列出，选了哪面、为什么）

| 取舍 | 选哪面 | 为什么 |
|---|---|---|
| 快 vs 彻底 | **快**（人肉门房，零代码） | 我们对"真实学生要什么"的认知是 0，任何超过一周的工程投入都是在给未验证的假设付钱 |
| 简单 vs 灵活 | **简单**（一次只服务一个人，手动跑） | 门房版的全部价值在信息，不在效率。做成自动化就失去了"在场观察他打开清单时的表情"这件唯一不可替代的东西 |
| 短期 vs 长期 | **短期换信息，长期不欠债** | 唯一的长期债是"门房版的护栏是流程不是代码"——见 §8 风险第 1 条，我给了偿还条件 |
| 降门槛 vs 绕过门槛 | **绕过** | 降门槛（做网页版/扩展）是几周工程，且 career-ops 的存在证明门槛不是绝对阻塞。先验证再付钱 |
| 先分发 vs 先补漏斗 | **先补漏斗第一分钟，但用门房版补，不用工程补** | 现在做分发等于把人倒进一个第一分钟就漏的桶，还烧掉唯一一次首发印象 |

### 5.3 排序：它排在 292 存量 / 回执测量 / 批次 B 的哪里

**排序尺不是"重要性"，是两个维度：① 这件事离"第一个非创始人拿到价值"还差几步 ② 它的信号延迟有多长。**

> **先说方法论上的诚实话**：**RICE（触达 × 影响 × 信心 ÷ 成本）在这里不可用。** 触达（Reach）今天等于 0，任何以触达为乘数的公式对所有候选方案都得 0 分——套进去只会得到一张假装精确的表。上一轮竞品调研已经指出过我们"用没校准过的分数假装精确"（§12.2 F 项），我不在这里再犯一次。**我改用「离第一个真实用户还差几步」排序，并逐条给理由。**

| 事项 | 离第一个真实用户几步 | 信号延迟 | 排序结论 |
|---|---|---|---|
| **人肉门房版首跑** | **0 步**（它本身就是那一步） | 当天 | **最高注意力，本周做** |
| **回执测量（`confirmed_at` 全 0）** | 不在这条线上 | **2-6 周** | **今天就启动，但不占注意力**——见下 |
| **292 个存量投递** | 不在这条线上，但是**社交前置** | 1-3 周 | **与门房版并行，归创始人日常动作**——见下 |
| **批次 B 剩余** | 1-2 步（M1 之前必须做完一部分） | 即时 | **拆开排，不能整包排**——见 §7 |

**为什么回执测量排"今天启动但不占注意力"**：
- 它的价值是回答"投出去有没有用"，而不是"有没有别人用"——**这是两个问题，混在一起排序必然排错**。
- 它的启动成本极低：`/mrweirdo-confirm` 已经存在，缺的只是"从来没有生产代码调用过它"（蓝图第四节第 1 条）。让创始人每两天手动跑一次，成本是分钟级。
- 它的信号要等 2-6 周才成型。**长延迟 + 低成本 = 今天就该按下去的按钮，而不是排在队列里等。** 这是排序理由，不是妥协。

**为什么 292 存量投递是"社交前置"而不是竞争项**（这是我这轮最想让 lead 记住的一条）：
一个创始人向同学开口推荐自己的工具时，他手里最有力的东西不是 README，是一句「**我上周用它投了 30 家，收到 2 个回音**」。今天他说不出这句话——42 天零投递、183 条历史投递零回音记录。**所以 292 存量投递不是"数据采集任务"，它是创始人自己算不算这个产品的用户的检验。如果创始人自己都不在用，任何分发动作都是虚的。**
但它必须**并行**而不是**串行**：它是创始人自己的手动动作，不占产品改动预算，且每次真跑批本来就要拍板人逐次点头（长期边界，`docs/specs/next-priorities.md`）。
**一条硬约束（红线，不排优先级）**：292 里的 **16 个 Lever 岗位在 §7 那三处修掉之前一条都不许投**，理由见 §7。

### 5.4 第一个真实用户从哪来（具体到可执行）

**找谁——按转化率排序，不是按人数**

| 优先级 | 谁 | 为什么是他 | 目标人数 |
|---:|---|---|---:|
| 1 | 创始人直接认识的、**今年春天投过实习但没拿到 offer** 的人 | 有痛、有可追问的过去行为、欠人情、愿意花 20 分钟 | 5 |
| 2 | 同校**非本专业**的找实习学生（商科找工科、工科找商科都行） | PROJECT_MEMORY 原则 3 的产品版：必须喂"不像我"的样本 | 3 |
| 3 | 学校社团 / 专业 club / 中国学生学者联合会（CSSA）群里公开征集 | 分发试探，但样本自选偏差大 | 视情况 |
| 4 | Reddit r/internships、r/csMajors | **本轮明确不做**——那是分发不是访谈，且漏斗还没补好，见 §5.2 最后一行 | 0 |

**怎么找——开场白决定一切**
不要说「我做了个工具，你试试」。这句话拿到的是礼貌性的"好啊"然后消失，且它污染后面所有回答（他会开始配合你）。
要说：**「我在研究大家怎么找实习，能不能占你 20 分钟，聊聊你上个投递季具体是怎么投的？我不卖东西。」**
产品只在访谈**结束后**出现，且以"我帮你跑一下"的形态出现，不以"你装一下"的形态出现。

**问哪 8 个问题（Mom Test 访谈法：只问过去发生的具体行为，不问"你会不会用"）**

1. 上个投递季你一共投了多少家？——**追问：这个数你是怎么知道的？**（能不能立刻说出数、以及从哪里数出来的，直接暴露他有没有在追踪，也直接检验我们"报告/看板"这条线的价值）
2. 带我过一遍你**最近一次**投递：从看到那个岗位，到你按下提交，中间发生了什么？花了多久？——**追问：中间有没有哪一步你停下来过？**
3. 那次你**用了什么**？（表格？备忘录？某个网站？）——**请他现在打开给你看。看他的屏幕，不要听他的描述。**
4. 你投完之后，怎么知道对方收到没有？**你上一次收到真人回音是什么时候、什么形式？**（这题直接测 `confirmed_at` 这条线在真实学生身上的分量）
5. 上个投递季有没有哪一次，你**开了个头没投完**？卡在哪一题上？（这题直接检验我们"缺信息压缩提问"这条最强的能力有没有对应真实痛点）
6. 你为找实习**花过钱**吗？花在什么上、多少钱？（付费意愿只能从过去的支出问出来，问"你愿意付多少"得到的答案是废的）
7. 有没有用过自动投递类的工具？——用过的：**为什么停了？** 没用过的：**你身边有人用吗？他们怎么说的？**（后半句是社交成本的探针）
8. 【唯一一道意向题，且只用来测风险偏好，证据强度我标为弱】有一个东西替你把表全填好、**你自己按提交**；另一个替你**连提交一起按了**。这两个你分别什么感觉？

**每场访谈只记三样东西**：他的原话（逐字，不总结）、他打开给你看的东西（截图/记下名字）、你**猜错了**的地方。

**怎么判断访谈结果是否推翻现有假设——三条可证伪的判据**

| 编号 | 现有假设 | 推翻信号（达到即认为假设被推翻） | 推翻后产品该怎么变 |
|---|---|---|---|
| **H1** | 学生的痛点是**投得不够多 / 填表太慢** | 5 人里 **≥3 人**在问题 1 说不出自己投了多少家，**或**明确说"我投得够多了，就是没回音" | 主轴从吞吐（投完 292）转向**回音与质量**，`docs/PRD-improvements.md` 那条"吞吐是最大杠杆"当场作废 |
| **H2** | 学生愿意让机器**以他的名义按提交** | 问题 8 里 **≥3 人**表现出明显不适；**或**问题 7 里出现"我朋友用了被坑/被刷"的具体故事 | 退到"帮你填、你点提交"那一格——**但那正是 career-ops 占着的位置**，意味着差异化要重打，属产品方向级决策，须拍板人拍 |
| **H3** | **装机门槛**是主要障碍 | 问题 3 里发现他们已经在用有学习成本的东西（浏览器扩展 / Notion / 自建表格），**且**问题 6 里有过真实支出 | 那门槛就不是意愿问题而是**认知问题**（没人知道有这东西），第一件事从"降门槛"改成"分发 + 首屏叙事" |

**饱和判据**：同一个痛点用**他们自己的话**在 3 人以上重复出现 = 该点饱和，停止追问该点。
**样本判据**：如果 5 个人之间**没有任何一个共同痛点**，结论不是"没需求"，是**我们选错了人群**——换一批人重来一轮，**不许在同一批人身上继续加问题**（加问题只会得到迎合）。
**记录纪律**（借 PROJECT_MEMORY 原则 2 的三态字段规矩）：每条判据只记 **是 / 否 / 没问到** 三态。**"没问到"绝不许当成"否"** ——上一轮那个把 `null` 和 `false` 一起塞进默认分支的 bug，在访谈笔记里同样会发生，而且没有测试会抓到它。
**反向守卫**：如果有人当场说「你现在就给我用」——**不要给安装包，给门房版**。这是一周内能产生第一个真实用户的唯一路径，把它当成访谈的成功出口，不是当成"顺便"。

## 6. Metrics（指标）

**主指标必须换。** 现行的隐含主指标（投递条数）与本轮目标（有人用）无关——投满 292 条，用户数仍然是 1。

| 类型 | 指标 | 现状 | 目标 | 测量时机 |
|---|---|---|---|---|
| **主指标 M0** | **看见价值**：非创始人拿到一份基于**他自己简历**的排序岗位清单，并**说出至少一条**「这条我会投」或「这条不对」 | **0** | **5 人**（14 天内） | 每次门房版跑完 |
| **主指标 M1** | **自己跑一轮**：非创始人在**自己机器**上从安装走到队列关卡 | **0** | **1 人**（30 天内） | 每次外部安装 |
| **主指标 M2** | **回来第二次**：同一个非创始人在 7 天内**主动**再跑一次 | **0** | **1 人**（45 天内） | 每次外部安装后追踪 |
| 次指标 1 | 访谈饱和度：同一痛点被 ≥3 人用自己的话说出 | 0 场访谈 | ≥1 个饱和痛点 | 5 场访谈后 |
| 次指标 2 | **第一分钟流失点**：外部用户在哪一步停下（人工记录，不做埋点） | 无记录 | 有记录即达标 | 每次外部安装 |
| 次指标 3 | 打分外部一致率：门房版清单里被对方判为"明显不对"的比例 | 未知 | **先测出来，不定目标** | 每次门房版跑完 |
| **护栏 1** | **门房版期间以他人档案发起的真实投递数** | 0 | **恒等于 0** | 每次门房版跑前后 |
| **护栏 2** | 不实陈述事件（含 Lever 三处未修期间投出的行） | 未知（无留痕） | **恒等于 0** | 每次真跑批 |
| **护栏 3** | 报告里"已提交"与页面实际结果不一致的行数 | **已知 ≥6**（Round 18 取证） | 归 0 | 每次真跑批 |

**M2 是这张表里唯一真正回答"有人用"的一格。** 第一次是人情，第二次才是需求。M0 和 M1 都可能是创始人的面子换来的。

**三条正交的产品目标**：
- **G1 可信**：产品交给用户的每一个数字都是真的。（今天不成立——`ashby_success` 那 6 张）
- **G2 可试**：一个学生在 20 分钟内、**不安装任何东西**，能看到属于他自己的结果。（今天完全不成立）
- **G3 可传**：他能用一句话向同学解释这是什么、以及它跟"海投机器人"的区别。（今天不成立——四条差异点压在免责声明里）

正交性验证：可信不保证可试（我们今天最接近可信，但完全不可试）；可试不保证可传（门房版可试，但完全不可传）；可传不保证可信（LazyApply 极其可传，极其不可信）。三者互不包含。

## 7. 反驳 lead：批次 B 的分类框架我不同意

> **lead 的判断**：「批次 B 里只有 B0（Ashby 阻塞信号接线）+ B1（工作授权对号入座问法）压在『能不能用』这条线上，其余四件是『别出事』不是『有人用』。」
> **我的立场：这个框架本身要驳，具体分项我同意一半、反对一半。**

### 反驳 0（最根本的一条）：对这个产品，「别出事」就是它的产品

这个产品今天能对一个陌生学生讲的**全部**故事，是四句话：不碰 LinkedIn/Indeed、数据不出本机、不投不相关的岗、不编造事实（`README.md:99-116`，上一轮竞品调研判定为"我们仅有的四条真实差异点"）。
**这四句话，每一句都是"别出事"类的。**
所以「别出事 ≠ 有人用」这个二分法，在别的产品上成立，在这个产品上**恰好把唯一的差异化资产整个降级了**。我们跟 career-ops 的差别只有最后一次点击；跟 LazyApply 的差别**全部**在这四条上。把它们归进"防御性工程"，等于说"我们的卖点是次要的"。

### 反驳 1：B3 的「投递留证」不是别出事，它是「有人用」的硬条件

**证据（A 级，Round 18 逐张打开核过）**：6 张文件名写 `..._ashby_success_...` 的截图，页面写的是 **「We couldn't submit your application」**；另 3 张 `post_submit` 画面无提交确认。
**推论**：产品交给用户的唯一交付物就是那份最终报告（`SKILL.md:471-496`），而**那份报告里"已提交 N 条"这个数字今天是假的**。
拍板人最在意的正是这个数字（蓝图第二节原话：「拍板人最在意的『投了几家、几家回了』不在这 5 步里」）。
一个新用户跑完一轮，报告说"投了 12 家"，他去邮箱一看只有 6 封确认信——他不会再跑第二次（M2 直接归零），而且他会告诉别人。**这不是"别出事"，这是产品唯一的输出物在说谎。**
**加一条 lead 可能没接上的线**：B3 的 `submission_evidence.mjs`（先读页面文案定判定、读不出写 `unknown`、禁止默认成功）**同时是回执测量的前置**——`confirmed_at` 要从 0 变成有意义的数，第一步得先定义"什么算真的投出去了"。**B3 不做，回执测量做出来也是建在假地基上。**

### 反驳 2：B0 只修了一半，而没修的那一半正是"卡住但不知道卡在哪"

**这是我实读代码得出的，不是转述 TASK 档案。**
`shared/ashby_apply_driver.mjs:1142` 现在确实带上 `note` 了（Round 28 提交 `360ff2f`）——**但同一行的 `if (sel)` 守卫还在**，而 `addPendingQuestion:1039-1040` 的第一句就是 `if (!item?.question || !item?.selector) return;`。
**后果**：找不到 CSS 选择器的阻塞题（下拉框形态），**题目连同原因一起蒸发**。用户看到的是"这行被跳过了"，报告里连"卡在哪一题"都没有。
而驱动本身正在为**四种**情形发出阻塞信号（`:540` 居住地事实未确认、`:546` 工作授权、`:633` 无归类的长文本题、`:644` 搬迁承诺政策未设）——其中好几种在 Ashby 上典型就是下拉框。
**所以：lead 说 B0 在「能不能用」这条线上是对的，但 B0 今天只完成了一半，剩下的一半恰恰是体感最差的那一半。** 这条要显式登记，别当它做完了。

### 反驳 3：B2 里的 Lever 不是"别出事"，是**正在说谎**，属红线，红线不参与排序

**我实读了 `shared/lever_apply_driver.mjs:255-279`，三处无条件回答，全部还在：**
- `:260` 「你是否有在美国工作的授权」→ **无条件 `Yes`**（不读档案，一个字段都不看）
- `:266` 「你目前在读 / 会返校继续学业吗」→ **无条件 `Yes`**（对一个即将毕业的大四生就是假话）
- `:271` 「你是否年满 18 岁」→ **无条件 `Yes`**

取证报告里有 **5 家真实 Lever 投递**，292 存量里有 **16 个 Lever 岗位**。
**PROJECT_MEMORY 第一条原则原文：「红线必须落成代码断言，写在文档里的红线等于没有。」** 这三行就是那条原则的现行反例，只不过换了个平台。
**红线不排优先级，红线是必修。** 我不同意把它归进"别出事"那一堆按顺序等——**它的正确处置是：修好之前，那 16 行不许投；这是一条今天就生效的约束，不是一个排期项。**

### 反驳 4（方向相反，我驳的是 lead 归进"能不能用"的那一件）：B1 的依据是 n=1

关卡 3 拍板人说「问『你有没有工作授权』这没人能知道」——**这句话是对的，但它来自一个 F-1 身份的人的自我观察，n=1。**
一个美国公民本科生看到"你是美国公民或绿卡吗"，会觉得这是一道废题；**只有国际生才需要对号入座。**
**我不是说 B1 不该做**（它该做，而且拍板已经过了）。我说的是：**lead 把 B1 归进「能不能用」这条线，用的证据强度跟 P2 画像一样——零。**
而 §5.4 的 8 个问题里，问题 5 和 H3 判据**恰好能在一周内把它验掉或验实**，成本是零。**先访谈再定 B1 的问法，比先做 B1 再猜对不对便宜得多。**

### 反驳 5（这条我承认是"叙事一致性"不是"安全事故"，主动降级）

B3 的另一半（写入侧统一上锁）：50 张投递截图 644 权限、architect 打开一张**邮箱电话明文可见**、38 份求职信含真名、`cover_letter.pdf` 全仓库零 `chmod`（Round 9）。
**我不夸大**：644 在一台单人 Mac 上的实际泄露风险很低，只有本机其他账号能读。**所以我把它从"安全"降级为"叙事一致性"**——但正因如此它仍然在"有人用"这条线上：README 把「数据不出本机」当四条卖点之一，第一个真实用户是创始人的熟人，他装完发现自己的简历、求职信、带邮箱电话的截图在家目录里全局可读，**这不是出事，是卖点当场被证伪**。

### 反驳小结（给 lead 的可执行版）

| 批次 B 分项 | lead 的归类 | 我的归类 | 建议 |
|---|---|---|---|
| B0 Ashby 接线 | 能不能用 | **同意，但只完成了一半** | 补掉 `:1142` 的 `if (sel)` 守卫与 `addPendingQuestion` 的选择器强制 |
| B1 对号入座问法 | 能不能用 | **部分不同意，依据 n=1** | 该做，但**排在第一轮访谈之后**，用真实回答定问法 |

| B2 附加：**Lever 三处** | 别出事 | **强烈不同意——红线** | **不排期，改成约束：修好前 16 个 Lever 岗不许投** |

**我同意 lead 的部分**：B2 的大多数分项（禁枪清单合并、居住地三态、学籍三态、年满 18、无限制授权）确实是"别出事"，它们只在有人真跑批时才起作用，按原顺序排没问题。

## 8. User Stories / Out of Scope / Dependencies / Risks / Open Questions

### User Stories（用户故事）

**US-1｜我想先看看这东西懂不懂我**（对应 G2 可试）
> 作为一个正在找实习的学生，我想在**不安装任何东西**的前提下，看到一份基于我自己简历的岗位清单，这样我才知道值不值得花半小时装它。
- ☐ 从收到简历到交出清单 ≤ 24 小时，清单每条附"为什么推荐/为什么跳过"
- ☐ 全程零真实投递（护栏 1 恒为 0），且跑在隔离家目录里，不污染创始人自己的库

## 9. 讨论中辩驳过的方向（Iterations = 2，4 个被否决方向）

**被否决方向 1：先降装机门槛（做网页版 / 浏览器扩展 / 免依赖版）**
第一轮的直觉答案，我自己写到一半推翻的。
**否决理由（是实证，不是判断）**：career-ops 的装法是 git clone + npm install + playwright 装 chromium + 跑 doctor，跟我们同量级，第三方教程标题直接写"30 分钟从零到第一次投递"（C 级：搜索摘要，未打开原页），而它的 star 数比我们大两个量级。**说明这个赛道的用户确实会为了这类工具跨过命令行门槛。** 降门槛是几周工程，换来的是一个**从没被验证过的画像**（P2 至今纯假设）。
**保留条件**：如果 H3 判据没被推翻（访谈发现他们连浏览器扩展都不装、也从没为找实习花过钱），降门槛就重新回到台面。

**被否决方向 2：先把 292 个存量投完，用真实漏斗数据说话**
这是最"正确"因而最危险的一条——它已经是拍板过的 P1，谁都不会反对。
**否决它作为"第一件事"的理由**：它产出的所有数据 **n 都等于 1，而且是创始人自己**。它回答"这东西对我有没有用"，不回答"有没有别人用"。全投完之后，用户数仍然是 1。
**但我不否决它本身**——见 §5.3，它是创始人的"社交前置"（说得出"我上周投了 30 家收到 2 个回音"，才有资格向同学开口），应当**并行**进行，且带一条硬约束：**Lever 那 16 行修好前不许投**。

**被否决方向 3：先改 README 首屏（零成本、零风险，上一轮就提过）**
上一轮竞品调研 §反驳 2 已经建议过，至今没做，看起来是唾手可得的一件。
**否决理由**：README 只有在**有人来看**的时候才有价值，而现在没有人来。更要命的是——**现在改，改出来的文案是创始人脑补的**，跟今天这版 README 是同一个作者、同一个信息基础。**正确顺序是：先访谈拿到他们的原话，再用他们的话写首屏。** 所以它不是"不做"，是"排在访谈之后"，而且届时它的质量会高一个数量级。

**被否决方向 4：先做 B1（工作授权对号入座问法）**
lead 把它归进"能不能用"这条线，我一开始跟着接受了。
**否决它作为第一件事的理由**：见 §7 反驳 4——它的全部依据是一个 F-1 身份的人的自我观察（n=1）。它该做，但**先访谈再定问法**，成本是零，收益是不用猜。

**（顺带记一条方法论，来自 PROJECT_MEMORY 原则 5 的双向扫描）**：找"为什么没人用"这件事，也必须双向扫。**汇点扫描**（顺着产品逐屏找哪里做得不好）我在 §2.1 做了；**源点扫描**（问"人本来该从哪条路来"）得出的是完全不同的答案——**根本没有任何一条路通向这个产品**：没有分发、没有入口物、没有一个人知道它存在。这两个方向给出的第一件事不一样，而我最终选的方案（门房版）是唯一同时落在两条线上的：它既补了第一分钟，又本身就是一条路。
