# 帮别人跑一次（操作卡）

> 一句话：你要拿**别人的简历**，在**你自己的电脑**上跑一遍这个产品，只跑到"打分排队"为止，
> **绝不真的投出去**。这张卡从头到尾照着做就行，不需要懂编程，也不需要看懂命令的意思。
> 命令一律**整段复制**到终端里，回车。

---

## 开始之前：两句大白话

**第一句：这个产品会在你电脑上开一个"家"，所有东西都放在里面。**
你自己的那个家在 `~/.mrweirdo-jobs`（`~` 就是你的用户文件夹）。
里面是你自己的简历、你的档案、你投过哪些岗位。
帮别人跑的时候，我们要给他**另开一个家**（一个临时文件夹），
让他的简历和答案全部落在那里，跟你自己的东西一点不挨着。

**第二句：告诉程序"用哪个家"的那个开关，只在一个命令窗口里有效。**
你每敲一段新命令，很多工具会**新开一个窗口**来执行它。
上一段设的开关，到下一段就没了——**开关一丢，程序就默认用你自己的家**。
这正是以前会出事的地方：前面几步都好好的，某一步悄悄写进了你自己的家，
而且**不会有任何提示**。

所以这张卡做两件事：
① 用**一次设置、整场有效**的方式打开关（不是每段命令临时打一次）；
② 在你自己的家里放一张**"施工中，勿入"的纸条**——
万一某一步真的漏了开关，程序会**当场停下来报错**，而不是默默写进去。

---

## 第 1 步：给他建一个家，并挂上"勿入"的纸条

先给这次代跑起一个代号（随便起，别用真名，比如 `s1`）。下面全文都用 `s1`，
你换成自己的代号就行。

**整段复制，回车：**

```bash
mkdir -p /tmp/concierge-s1/run-tmp
echo "/tmp/concierge-s1" > ~/.mrweirdo-jobs/.concierge_run_active
cat ~/.mrweirdo-jobs/.concierge_run_active
```

最后一行会回显 `/tmp/concierge-s1`，说明纸条贴好了。

这张纸条的意思是："我自己的家现在暂停使用，这次的活儿都在 `/tmp/concierge-s1` 里干。"
从这一刻起，任何一步只要**漏了开关**、想往你自己的家里写东西，
程序会**直接停下**并打印一段话，告诉你该带哪两个开关重跑。
**它不会写坏任何东西，只会拒绝干活。**

> ⚠️ 纸条贴着的时候，**你自己的求职也跑不了**（这是故意的）。
> 第 6 步会把它撕掉，撕掉之后一切照旧。

---

## 第 2 步：打开两个开关（关键：要"整场有效"）

**不要**把下面两行写进某一段命令里；要**先在终端里设好，再从这个终端启动你平时用的 AI 工具**
（Claude Code 或 Codex）。这样整场对话里的每一段命令都会自动带上这两个开关，
不会出现"某一段漏了"的情况。

打开"终端"应用，整段复制，回车：

```bash
export MRWEIRDO_HOME=/tmp/concierge-s1
export MRWEIRDO_ONBOARD_TMP_DIR=/tmp/concierge-s1/run-tmp
echo "家=$MRWEIRDO_HOME  过程文件=$MRWEIRDO_ONBOARD_TMP_DIR"
```

它会回显这两行值。**确认两行都指向 `/tmp/concierge-s1` 再往下走。**

然后**就在这个终端窗口里**敲 `claude`（或 `codex`）启动工具，开始这次代跑。

> 为什么两个开关都要设？
> 第一个管"档案、简历、数据库"，第二个管"过程文件"——
> 过程文件里有**他的表单上填了什么**、**他哪些个人问题没答**、**给他找到的岗位清单**。
> 现在第二个开关不设也会跟着第一个走（这是这一轮刚改好的），
> 但**明写出来更保险**，也让你一眼看得出这次跑在哪。

---

## 第 3 步：把他的简历放进去

把他的简历文件（PDF）放到你电脑上一个临时位置，比如桌面，然后：

```bash
bash scripts/intake_resume.sh ~/Desktop/他的简历.pdf
```

（把路径换成真实文件名。）
如果你**忘了第 2 步**，这一句会**当场报错**并告诉你怎么办——这就是纸条在起作用。

---

## 第 4 步：跑到"排好队"为止，然后停

在 AI 工具里正常走流程：**简历分析 → 找岗 → 打分入库**。
产品自己会把进度标成 `[Step 1/7]`、`[Step 3/7]`、`[Step 4/7]`。

**看到 `[Step 4/7] 入库完成 / Stored` 那张表格，就停下来。这是本次的终点。**

**下面这些绝对不做：**

- ❌ 不要进入 `[Step 5/7] Queue gate`（那是"确认后开始真投"的关口）
- ❌ 不要回复"开始"、"确认"、"go" 这类同意投递的话
- ❌ 不要跑任何带 `--real` 字样的命令（那就是真的往公司投）
- ❌ 不要让它打开浏览器去公司网站

如果 AI 主动问你"要不要开始投递"，回答**"不投，只看队列"**。

想看看给他排出了什么队，直接让 AI **"把队列预览给我看，不要投"** 就行。
也可以自己跑这一句（**只看不投，不会提交任何东西**）：

```bash
node shared/apply_supervisor.mjs --dry-run | head -40
```

如果它回你一句 `Missing role targets`，说明前面的步骤还没走完（还没生成他的求职方向），
不是出错——把前面的步骤走完再看。

---

## 第 5 步：跑完了，确认没污染到你自己

**整段复制，回车。三条检查，逐条看结果：**

```bash
echo "--- ① 我自己的家，在这次代跑期间有没有被动过（应该只列出纸条本身，或者什么都不列）"
find ~/.mrweirdo-jobs -newer ~/.mrweirdo-jobs/.concierge_run_active

echo "--- ② 老的公共临时文件夹有没有新东西掉进去（应该什么都不列）"
find /tmp/mrweirdo-onboard -newer ~/.mrweirdo-jobs/.concierge_run_active 2>/dev/null

echo "--- ③ 他的东西是不是都在沙箱里（应该能看到 profile.json / resume.pdf / jobs.db / run-tmp）"
ls -la /tmp/concierge-s1
```

**怎么读结果：**

- ①②**一行都不打印**＝ 干净，你自己的东西一个字节没动。
  （这两条命令的意思是"列出比那张纸条还新的文件"——纸条是代跑开始时贴的，
  所以只要什么都没列出来，就说明代跑期间没人动过你的东西。这两条已实测过一遍，
  正常情况下就是**空白**，不会打印那张纸条自己。）
- ①如果列出了别的文件 → **先别清理**，把那份清单发给工程那边看，这说明有一步漏了开关。
- ③里应该看到他的档案和简历；`run-tmp` 文件夹里是过程文件。

---

## 第 6 步：清理

确认第 5 步干净之后，**整段复制**：

```bash
rm -rf /tmp/concierge-s1
rm ~/.mrweirdo-jobs/.concierge_run_active
rm ~/Desktop/他的简历.pdf   # 把路径换成你第 3 步用的那份，别忘了删
echo "清理完成，你自己的求职功能已恢复正常"
```

最后关掉第 2 步那个终端窗口（开关随窗口一起消失）。
以后你自己跑求职，**不要**再带那两个开关。

---

## 现在还存在的限制（如实告诉你，本轮没修）

1. **沙箱里的岗位数据库文件权限偏松。**
   `/tmp/concierge-s1/jobs.db` 是"同一台电脑上的其他账号也能读"的权限（644）。
   他的档案、简历、答题留痕这三样是锁好的（只有你能读），**唯独岗位与投递记录这一份没锁**。
   在你自己一个人用的笔记本上风险很低；但如果这台机器有别人的账号，请知道这一条。
   （统一上锁属于另一件排期中的活，本轮没做。）

2. **纸条只在"程序自己去找家"的时候起作用。**
   如果有人手动把开关指向你自己的家，程序同样会拒绝——这没问题；
   但如果有人绕过这些脚本、直接用文件管理器往里拷东西，纸条管不了。

3. **这张卡只覆盖"跑到打分为止"。**
   真投递（Step 5 之后）在代跑场景下没有验证过，**不要在别人的简历上试**。

## 出问题时的一句话对照

| 你看到 | 什么意思 | 怎么办 |
|---|---|---|
| `refusing to use ... a concierge run is in progress` | 某一步漏了开关，被纸条拦下了 | 按它打印的那行命令重跑；或者回到第 2 步重新开一个带开关的终端 |
| `intake_resume.sh` 报同样的话 | 简历差点被拷进你自己的家 | 同上。**没有拷进去**，可以放心 |
| 第 5 步①列出了一堆文件 | 有一步真的写进了你自己的家 | 别清理、别删，把清单交给工程那边查 |
| 想中途放弃 | — | 直接做第 6 步清理即可，没有半成品需要收尾 |
